# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。

## 应急演练管理：可重建、可迁移的一条链路

应急演练不再使用 `seed.ts` 里的静态占位数据，单独走一条可重建、可迁移的链路，代码集中在
`frontend/src/data/emergency/`，构建与本地共用同一条命令：

```bash
cd frontend
npm ci                 # 严格按 package-lock.json 安装，版本逐位一致
npm run verify         # 应急演练链路自检（确定性/幂等/续跑/把关/并发/待办/自检）
npm run build:deploy   # 先自检后构建；自检不过不产出
```

容器部署同样走这一条：`frontend/Dockerfile` 多阶段构建（`npm ci` → `npm run build:deploy`
→ nginx 托管静态产物，SPA 路由回退见 `frontend/nginx.conf`），`docker compose up --build` 即可。
依赖版本钉在 `package-lock.json`，`package.json` 的 `supportedArchitectures` 同时声明
linux/darwin，本地与镜像构建装出的依赖一致。

### 链路口径（均写死在 `constants.ts` / `generator.ts`）

- **确定性初始化**：`generator.ts` 按演练编号（`EMER-0001..0010`）稳定生成样例，所有取值是
  编号的纯函数（FNV-1a），不依赖随机数与当前时间；数据集带版本 `seedVersion` 与内容指纹
  `seedHash`，本地重建与线上落库逐字节一致，页面顶部显示指纹可核对。
- **幂等可续跑**：`pipeline.ts` 按行打检查点（`pipeline-ledger`）。反复执行初始化不改动已有
  演练记录、不冲掉已评估结论；迁移跑到一半中断，重跑只补未处理序号，从断点接着做。
- **存量迁移**：切换日 `CUTOVER_DATE = 2026-10-06` 之前的往期数据按**计划日期**升序整体搬入
  （巡检等模块可复用同一迁移器，按各自巡检日期字段配置）。必填字段缺失的记录整笔进“待确认
  暂存”，页面逐条列出缺失字段等人工确认，确认补全后才落正式台账，可放弃。
- **回补口径（我定的）**：切换日前**已举办（演练中/已评估）却没留下评估结论**的，回补为
  `待补评估` 占位（明确标注待补，绝不替演练编造成效），由组织人员在页面“补录结论”；从未组织
  （待组织）的不算结论缺口，原样搬入。**老数据沿用原有结论，新口径自切换日起算。**
- **判重口径（我定的）**：按业务自然键 **演练编号** 判重（`DEDUP_FIELD`），`id` 只是存储行号
  不参与判重。同批次内编号撞车的多笔都保留、由自检挑出；跨批次与正式台账撞编号时正式台账优先、
  存量行跳过不覆盖。
- **岗位把关**：只有 `组织人员` 能落评估结论、变更台账、确认暂存与闭环待办；`参演人员`、
  `只读访客` 只读，越权提交整笔驳回（页面右上角可切换岗位验证）。
- **并发提交**：每行带乐观锁版本号 `v`。同一时刻两笔提交只让先到的入账并推进版本，后到的按
  版本冲突整笔回退；已评估结论不可二次覆盖。
- **处置结论回写待办**：评估/补录后结论回写到独立入口「评估处置待办」（路由
  `/emergency-todos`），按台账行 id 一一对应（编号撞车不合并），补录时原地更新不增条数；
  待闭环（已评估 + 待补评估）条数与待办条数恒等，页面与概览都显示一致性，对不上会标红。
- **收尾自检**：自检逐条列出 ①演练编号撞车 ②参与班组缺人（班组为空或参演少于 2 人）
  ③评估结论与演练状态互相顶牛，每条写明演练编号、环节与缘由。自检条数由同一个
  `emergencyMetrics()` 供给演练页看板与运营概览，两处永远是同一个数，一起变化。
